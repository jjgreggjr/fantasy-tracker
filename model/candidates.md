# Candidates

The living list the weekly retrospective feeds (PLAN_MODEL.md "Phase 5"). Every model candidate is a string
`python -m model.trial --candidate <string>` runs as is (a string starting with `-` needs the `--candidate=<string>` form) (several strings in one row = one composed variant, one flag each);
the verdict lands in `model/reports/trials.md` and is copied into the status column here. `python -m model.trial --list`
shows the families and which columns are in the serving inputs. E_pts candidates are listed too, but `trial.py` does not
cover E_pts: its lever is `ff/score.py`.

Status values: `open` / `tested: <verdict>` / `adopted <date>` / `needs a feature first` / `not a trial.py candidate`.
