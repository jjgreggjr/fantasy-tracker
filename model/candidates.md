# Candidates

The living list the weekly retrospective feeds (PLAN_MODEL.md "Phase 5"). Every model candidate is a string
`python -m model.trial --candidate <string>` runs as is (a string starting with `-` needs the `--candidate=<string>` form) (several strings in one row = one composed variant, one flag each);
the verdict lands in `model/reports/trials.md` and is copied into the status column here. `python -m model.trial --list`
shows the families and which columns are in the serving inputs. E_pts candidates are listed too, but `trial.py` does not
cover E_pts: its lever is `ff/score.py`.

Status values: `open` / `tested: <verdict>` / `adopted <date>` / `needs a feature first` / `not a trial.py candidate`.

## Batch of 2026-10-16 (16 trials, `model/reports/trials.md`)

Nothing ships. Every candidate moved pick accuracy by at most 0.002 in any year; dRMSE ranged -0.013 to +0.014 and
nothing was negative in both 2025 and 2024 with a 2025 interval clear of zero. DIRECTION ONLY (negative both years,
interval spans zero): `+family:eff` (-0.004 / -0.008), the un-pruned raw-count lags (-0.001 / -0.011), the pruned
context columns (-0.005 / -0.009), weaker regularisation (-0.002 / -0.001). A kitchen-sink variant of every opt-in
family plus recency weighting was worse (+0.014 on 2025). Reading: the flat model is saturated on the information
it has; recombining it does not help. The next gains need new information (market lines, archived platform
projections) or a different composition (a model + Sleeper average scored 0.683 vs 0.681 / 0.678 on frozen weeks
4-5, 1,039 rows; worth a scoreboard comparator, not yet a decision).
